# ADR-0004：题面与C++编译MVP

- 日期：2026-10-01（Asia/Shanghai）；作者：根Agent /Architect。
- 状态：按用户明确范围采用；接口为compile-mvp/0.1.0，独立实现审阅待完成。
- 用户要求：前后端同时开工，显示题面、输入C++、判断编译成功，不考虑沙箱；随后授权并行开发和独立审阅。

## 范围裁定

当前优先交付一个实际可用的本机MVP。保留原Phase1 Mini Judge设计作为未来执行 /判答案路线，但其runner /cgroup /reaper完整前置不阻止此只编译MVP。旧“前端只交付MD”由本次实际开发授权取代。

MVP包含一份内置A+B题面、代码编辑器、编译按钮、成功 /错误诊断 /服务错误状态。真实g++以C++20编译并链接源文件，exit0才成功；不只检查语法，不运行生成程序，不检查答案。编译记录仅请求内存和临时目录，不引入业务DB /队列 /登录 /保存历史 /S3。

API仅做题库读取、输入校验与compiler HTTP转发，独立compile-worker持有g++；保留API不编译 /运行源码的基础原则。Linux编译环境用Docker管理，Docker在此是开发工具环境，不声明Sandbox或生产安全能力。服务只绑定localhost，网页明确“仅检查编译，未运行程序”。

保留有限源码 /诊断、单个编译并发与超时以保证页面稳定，不增加生产沙箱体系。外部部署、恶意源码执行与完整判题仍不在范围内。

## 验收与后续

浏览器显示真实API题面，C++有效程序编译并链接成功；语法错误 /缺少main返回失败和具体诊断；空 /超大 /未知题目输入拒绝；服务关闭时显示服务错误且可重试。测试必须调用真实编译器，不用固定成功响应替代。

独立review覆盖本次API /worker /前端闭环与此范围；文档和PROGRESS同步，未实现能力保留。出现新的环境或工程阻塞时按用户原规则单开MD并停止。
