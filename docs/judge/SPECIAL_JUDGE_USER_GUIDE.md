# 学生页面与特殊判题使用指南

本增量提供内置构造题规则、教师上传 C++ 特判及分模式信息展示。页面服务就绪后打开 [本机题库](http://127.0.0.1:5173)。截至2026-10-04当前因自动审批通信复发已停止，Web/API/Judge未在线，最终产品验收未完成。23项真实矩阵及教师上传AC2/2已通过对应版本；下载/编辑修正和重启持久化仍待实测。最终状态只看 [PROGRESS](../../PROGRESS.md)，接续步骤见[交接](../handoffs/2026-10-04-special-judge-paused.md)。功能协议见 [special-judge/0.1.0 契约](SPECIAL_JUDGE_CONTRACT.md)，原固定猜数交互题操作见 [三模式指南](MODES_USER_GUIDE.md)。

## 三种模式各自显示什么

顶栏手动选择学生、教师或工程师。没有账号登录，任何本机使用者都能切换模式；本机演示不能用来保护真实课堂的隐藏数据。

| 模式   | 面向的操作与信息                                                                                                                                                                   |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 学生   | 浏览题库、题面、输入输出要求、公开样例、解题提示、时间/内存限制；编辑 C++20 后编译或运行测试。结果显示整体判定与通过数量，保留本人编译诊断；不显示隐藏逐例数据、特判反馈和工程证据 |
| 教师   | 学生操作，以及上传题目、隐藏数据和 C++ 特判；运行后查看每例输入、参考答案、选手输出、判定、耗时和特判反馈，用来核对题目与判定规则                                                  |
| 工程师 | 教师操作，以及题目工程说明、比较器标识、编译阶段、特判/交互器记录、运行 ID、源码/数据/产物摘要、镜像、退出码和 OOM 等调试事实；另有“工程调试”页面                                  |

学生页面保留必须遵守的交互格式、查询次数与刷新输出要求。token/字节比较、默认演示解法、容器执行、墙钟时间含启动开销、编译器版本与阶段耗时等放在工程师展示中。教师填写“提示”时只写公开的解题条件；“工程说明”字段仅工程师题目响应与页面可见，不能把隐藏答案写进公开提示或公开样例。

切换模式会取消在途请求并清空旧结果，同题编辑内容保留；修改代码后旧结果会标为过期，需要重新运行。“工程调试”的已配置状态只证明配置可读，不等于某道题已经判题通过。

## 教师先选择判定方式，再准备文件

切换教师或工程师模式，点击“上传题目”。选择“标准题 / 构造题”后，答案判定有四种方式；交互题仍使用固定猜数协议。

| 页面选项                                               | 适用题目                             | 每例数据                                                         | 隐藏用例上限 |
| ------------------------------------------------------ | ------------------------------------ | ---------------------------------------------------------------- | ------------ |
| 按空白分隔比较（tokens-v1）                            | 存在固定标准答案、允许空白差异的题   | 同名 `.in` + `.out`；token 内容严格一致，不做数值误差容忍        | 8 例         |
| 精确字节比较（exact-v1）                               | 输出格式与换行也必须完全一致的题     | 同名 `.in` + `.out`                                              | 8 例         |
| 内置规则 · 不相邻排列（nonconsecutive-permutation-v1） | 下文固定构造条件，多种答案可正确     | 只上传 `.in`，不上传 `.out`                                      | 8 例         |
| 教师上传 C++ 特判（cpp-special-v1）                    | 自定义构造条件、其他多个合法答案的题 | 每例必须 `.in`；同名 `.out` 可选；另由源码区域提交 `checker.cpp` | 4 例         |
| 交互题 · 固定猜数协议                                  | 选手通过至多十问猜 1–1000 秘密数     | 只上传 `.in`，每份一个秘密整数；不上传 `.out` 或交互器           | 8 例         |

数据文件如 `01.in`、`01.out`。主体须以小写字母或数字开头，其后可用小写字母、数字、下划线、短横线，最多 64 字符；不带目录，不能重名，不使用 con/prn/aux/nul 或 com/lpt 开头的主体。没有对应 `.in` 的 `.out` 会被拒绝。

每份数据与特判源码分别最多 64 KiB；整个题目描述、源码、数据及 multipart 请求最多 1 MiB。公开样例为 1–4 组，每组输入和输出分别最多 4 KiB，所有模式都能看到；它们不自动替代隐藏测试数据。题目描述整体最多 64 KiB，页面逐项显示字节数。时间限制可设 500–5000 ms，内存可设 32–256 MiB；交互题默认 5000 ms，其他默认 2000 ms/64 MiB。

## 内置构造题：多个答案都能 AC

“构造不相邻排列”要求输入一个整数 `n`，`1 ≤ n ≤ 1000`。有解时输出 `1..n` 的排列，每个数字恰好出现一次，任意相邻数字之差的绝对值不能为 1。

- `n = 2` 或 `3`：没有解，只输出 `-1`。
- `n = 1`：输出 `1`。
- 其余 `n`：必须输出合法排列，不能用 `-1` 代替。

例如 `n = 4` 时，`2 4 1 3` 和 `3 1 4 2` 都正确；`1 2 3 4` 不正确。判定会检查数量、整数范围、重复、相邻差与多余内容，并不要求照抄公开样例的顺序。

教师选内置规则后，可点击“填入构造题说明与样例”，再上传只含一个合法 `n` 的 `.in` 文件。建议覆盖 `1`、`2`、`3`、最小有解值 `4`、奇数和最大值；它们仍须遵守最多 8 例。该规则只适用于这一组固定数学条件；更换题意时应选择教师 C++ 特判并编写相应规则。

## 上传、编辑与下载 C++ 特判

1. 在“答案判定”选择“教师上传 C++ 特判”。填写题面、输入输出条件、公开样例和选手 C++20 起始模板；它们应描述同一套合法答案规则。
2. 可以点击“填入示例特判”，也可读取本地 UTF-8 `.cpp` 文件，或直接在“特判源码 · checker.cpp”文本区编辑。示例对应上面的不相邻排列规则；选择自定义特判不会自动强制你的题目采用该规则。
3. 本地文件可以有自己的 `.cpp` 名称，页面读取后发布名称固定为 `checker.cpp`。“下载当前 checker.cpp”保存当前编辑内容；发布也使用这份当前内容。只读取文件没有替代最终发布操作。
4. 在隐藏测试区域选择 1–4 个 `.in`，按需要添加同名 `.out`。未提供参考答案时，特判仍收到一个存在的空参考答案文件。
5. 发布后打开新题，先用正确解法和错误解法分别运行测试，在教师模式查看判定及反馈；必要时切工程师看特判编译和运行事实。

可直接查看或保存仓库示例：[checker.cpp](../../testdata/special-judge-example/checker.cpp)、[sample.in](../../testdata/special-judge-example/sample.in)、[sample.out](../../testdata/special-judge-example/sample.out)。源码自包含，使用 C++20 标准库文件流，不依赖 testlib。页面示例、下载和发布使用同一份源文本，并有与仓库示例一致的可信检查。

发布成功表示题面、文件和源码格式符合上传规则并已保存，不表示 C++ 特判编译成功，也不表示你的数学检查完整。每次运行测试才实际编译并执行特判。当前没有已发布题目的编辑/删除页面；发布会生成新 ID，不会覆盖内置题或已有上传题。

## 特判读文件与返回规则

特判是一个独立 C++ 程序，通过三个路径参数读取本次用例：

| 参数      | 内容                            | 使用要求                                                                      |
| --------- | ------------------------------- | ----------------------------------------------------------------------------- |
| `argv[1]` | 输入文件 `/data/input.txt`      | 用于恢复本例的题目条件；数据不合法属于题目配置问题                            |
| `argv[2]` | 参考答案文件 `/data/answer.txt` | 对应可选 `.out`；未上传时为空文件；构造题可不依赖其内容                       |
| `argv[3]` | 选手输出文件 `/data/output.txt` | 读取完整原始 stdout，检查全部要求和多余内容；页面展示截断不影响这里的原始内容 |

调用形式固定为 `checker /data/input.txt /data/answer.txt /data/output.txt`，因此 `argc` 应为 4。特判 stdin 为空，不从 stdin 读取上述内容，不覆盖这些文件；反馈可写入 `std::cerr`。不接受二进制、脚本、其他头文件、testlib 或自定义编译参数。

| 特判返回         | 判定         | 作者应怎样使用                                                                |
| ---------------- | ------------ | ----------------------------------------------------------------------------- |
| `0`              | AC           | 已检查完整输出，所有条件满足                                                  |
| `1`              | WA           | 输出违反题目要求，例如重复、越界、遗漏或多余内容                              |
| 其他值，例如 `2` | SYSTEM_ERROR | 文件无法读取、题目输入不合法、特判自身异常等；不要将题目配置错误返回为学生 WA |

特判源码编译失败、特判超时、内存/输出超限、异常退出或基础设施故障都属于 SYSTEM_ERROR，不能变成选手 CE/RE/TLE/MLE。选手自身 CE、RE、TLE、MLE、OLE 优先；只有选手成功运行且未超限才进入答案特判。教师能看到最多 1024 字节的特判反馈，学生只看到整体判定；调试细节在工程师模式。

写自定义特判时先明确“所有正确输出需要满足哪些条件”，逐条检查，而不是仅比较一个示例答案。使用参考答案时也须判断它在题意中扮演什么角色，例如最优值或存在性证明；示例 `.out` 不自动代表唯一合法排列。

## 发布后的题目自验

用能独立说明正确性的解法测试 AC，再构造违反各项条件的解法测试 WA。对于上面的排列题，应分别覆盖重复、遗漏、越界、相邻差为 1、多余 token、`n = 2/3` 错报有解，以及有解时错报 `-1`；至少用两种不同合法排列确认没有锁死样例顺序。

如果正确解法返回 SYSTEM_ERROR，教师先看特判反馈，工程师看编译与运行证据，确认是选手程序、题目文件还是特判自身的问题。不能把发布成功当作这些测试已通过，也不能把学生整体错误倒推为某个隐藏用例错误。

上传数据持久保存在本机，正常 API/Judge 重启后应保留；本增量的真实重启验证仍在验收中。提交源码和结果尚无持久历史页面。程序不应依赖网络、宿主文件或其他用例内容。

## 工程师与各 Agent 的职责

工程师题目说明解释 token/字节比较、默认模板、独立受限运行与墙钟耗时。上传特判使用独立 Judge 编译和执行，API 与 Windows 宿主不运行它：特判编译上限 10 秒/512 MiB，逐例特判运行上限 2 秒/64 MiB/32 进程，任务总预算 70 秒；选手限制另按题目设置。总预算还包括容器控制和清理，不保证所有最大规格组合都能完成。CPU 与内存峰值未采集时显示“未采集”，不估算。

| 职责                               | 当前工作与交付边界                                                                                                                                                                        |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| root / 集成 Architect、Builder     | 维护契约、API 分模式投影和可信快照绑定；串行执行真实环境、判题、取消/停止、上传重启与浏览器验收；记录版本、证据、PROGRESS、任务卡与最终交接                                               |
| 模块 Builder                       | 题库/store/Judge 按受审契约实现规则、上传与执行；前端仅维护 React/TypeScript 页面、上传表单、模式缓存/取消与反馈；生命周期 Builder 只修获分配的停止验证脚本。出现验收反馈按已认领路径修正 |
| 文档 Builder                       | 按实际源码与证据整理本使用指南和问题索引，保留历史因果、失败与验证范围；不运行真实服务、不替代实时进度台账                                                                                |
| 独立 Architect / Security reviewer | 独立审阅设计、实现和真实证据，复核学生字段投影、上传边界、隔离、摘要与清理；源码/镜像/证据绑定齐全后才签最终产品结论，自检不登记为独立审阅                                                |
| 用户                               | 处理新未知外部阻塞；若影响进展，Agent 按已定规则记录并停止。已明确授权的已知恢复及本轮实现修正由对应 Agent 完成                                                                           |

当前范围仍是本机手动模式、C++20、文件用例与固定猜数交互；真实账号权限、任意交互器上传、更多语言、异步持久提交和公网部署未纳入本增量。问题前因、方案与验证入口见 [问题索引](../issues/README.md)。本轮已停止在恢复验收阶段，最终完成状态只看 [PROGRESS](../../PROGRESS.md)。文档Agent交付后由root接收这两份入口文件并补充停止事实，职责执行详情看当前交接。
