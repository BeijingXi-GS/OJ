## 新问题的记录与收束

1. 新问题建立 `YYYY-MM-DD-简短问题名.md`，写明背景目标、发生时间、实际执行者、授权范围和影响任务。
2. 按操作顺序记录已发起动作与实际结果。未创建的进程写“未执行”；命令失败、测试 SKIP、实现通过与产品通过分开。错误只保留脱敏内容。
3. 分开写“已确认事实”“原因推测”“缺失证据”。方案应说明为什么针对当前事实、改动边界、数据保留方式及恢复条件，不能把候选原因写成结论。
4. 新未知外部问题默认交用户；阻碍后续进展时完成档案和 PROGRESS 的停止位置后停止。已获授权的已知恢复、当前实现和审阅修正由对应 Owner 按范围处理，授权补录到档案。
5. 同一问题的新恢复证据追加原档，不覆盖旧失败。复验必须包含实际结果和适用独立审阅，满足恢复条件后才能关闭；只启动进程或局部测试 PASS 不足以关闭产品验收问题。
6. 在本索引追加档案入口；任务状态、Owner 和下一步仅由 PROGRESS 维护。规则来源见 [AGENTS](../../AGENTS.md) 与 [DEVELOPMENT](../../DEVELOPMENT.md)。
